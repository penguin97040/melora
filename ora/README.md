# ora

Shared code for unofficial Spotify desktop clients, starting with Melora. It defines which
features every client has and holds the logic behind them, so a feature change reaches every
client at once.

Melora and ora are **unofficial and not affiliated with, endorsed by or sponsored by Spotify**.
They use only Spotify's official Web API and Web Playback SDK.

| Path | What it is |
|---|---|
| `crates/ora-types` | Plain serde data and the `Feature` registry. Builds for `wasm32-unknown-unknown`; TypeScript bindings are generated by its tests |
| `crates/ora-core` | Shared logic with no UI or Tauri dependency |
| `crates/ora-tauri` | The `ora` Tauri 2 plugin that exposes `ora-core` to a client's main window |
| `sdk-bridge/` | The single JavaScript file that will host the Web Playback SDK |

## Bring your own Client ID

There is no shared Spotify app. Each person creates their own app in the
[Spotify Developer Dashboard](https://developer.spotify.com/dashboard) and types its Client ID
into the client. Sign-in uses Authorization Code with PKCE, so no Client Secret is ever used or
stored. Tokens are kept only in the operating system's credential store and in memory.

## Boundaries

`scripts/check-ora-boundaries.sh` (run by `npm run check`) fails if `ora-core` depends on
`tauri`, if `ora-types` stops building for WebAssembly, or if the generated bindings are stale.
