# ora

Melora's Spotify core. It defines Melora's features and holds the logic behind them in Rust,
separate from the UI, so every Spotify rule lives in one tested place.

Melora and ora are **unofficial and not affiliated with, endorsed by or sponsored by Spotify**.
They use only Spotify's official Web API and Web Playback SDK.

| Path | What it is |
|---|---|
| `crates/ora-types` | Plain serde data and the `Feature` registry. TypeScript bindings are generated by its tests |
| `crates/ora-core` | Spotify logic with no UI or Tauri dependency |
| `crates/ora-tauri` | The `ora` Tauri 2 plugin that exposes `ora-core` to Melora's main window |
| `sdk-bridge/` | The single JavaScript file that will host the Web Playback SDK |

## Bring your own Client ID

There is no shared Spotify app. Each person creates their own app in the
[Spotify Developer Dashboard](https://developer.spotify.com/dashboard) and types its Client ID
into Melora. Sign-in uses Authorization Code with PKCE, so no Client Secret is ever used or
stored. Tokens are kept only in the operating system's credential store and in memory.

## Boundaries

`scripts/check-ora-boundaries.sh` (run by `npm run check`) fails if `ora-core` depends on
`tauri`, or if the generated bindings are stale.
